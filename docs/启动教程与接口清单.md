# Go2-W 遥测监控系统 —— 服务接口清单 & 手动启动教程

> 面向小白用户的完整手册。读完这篇，你可以手动启动整套系统。
> 系统部署在 **80 服务器**（192.168.1.80，Ubuntu 22.04），浏览器访问入口是
> `http://192.168.1.80:8000`

---

## 一、系统由哪些部分组成（先理解整体）

```
┌────────────────────────────────────────────────────────────┐
│  机器狗 Go2-W (192.168.123.161 / .18)                       │
│   ├─ DDS 状态流 (500Hz) → 关节/IMU/电池                     │
│   ├─ 激光雷达 → 点云 (供三维重构)                           │
│   └─ 深度相机 RealSense (扩展坞 192.168.123.18)             │
└──────────────┬─────────────────────────────────────────────┘
               │ 机器人专网 enp0s31f6 (192.168.123.222/24)
┌──────────────▼─────────────────────────────────────────────┐
│  80 服务器上运行 4 个独立进程 (tmux 会话)                    │
│                                                             │
│  ① collector.py   采集状态 → InfluxDB + state.json           │
│  ② pc_worker.py   采集点云 → pc_cache.json                  │
│  ③ front_cam_worker.py  采集前置相机 → latest_front.jpg     │
│  ④ server.py      FastAPI 网页 + 所有 API (端口 8000)       │
│                                                             │
│  另：深度相机由机器狗扩展坞上的 rs_capture 服务提供          │
└─────────────────────────────────────────────────────────────┘
```

**关键点**：①③④ 都在 80 服务器的 tmux 里跑；深度相机（rs_capture）在**机器狗扩展坞**（192.168.123.18）上跑 systemd 服务。

## 二、完整 API 接口清单

### A. 机器人状态类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查：服务器/机器人是否在线、采集频率 |
| GET | `/api/state` | 最新状态快照（IMU/电机/电池/足底力/运动模式） |
| GET | `/api/history/{measurement}` | 历史曲线（power/imu/battery/motor/foot_force） |

### B. 数据录制类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/record/status` | 当前录制状态 |
| POST | `/api/record/start?label=xxx` | 开始录制（可带标签） |
| POST | `/api/record/stop` | 停止录制并保存会话 |
| GET | `/api/sessions` | 列出所有已录制会话 |
| POST | `/api/record/label` | 为当前录制设置标签 |

### C. 数据集导出类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dataset/export/{session_id}` | 导出 HuggingFace 格式 |
| GET | `/api/dataset/export/lerobot/{session_id}` | 导出 LeRobot v2 格式 |
| GET | `/api/dataset/download/{session_id}` | 打包下载导出结果 |

### D. 定时录制类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/schedule` | 列出定时规则 |
| POST | `/api/schedule` | 新增规则（body: JSON） |
| DELETE | `/api/schedule/{rule_id}` | 删除规则 |
| POST | `/api/schedule/{rule_id}/toggle` | 启用/禁用规则 |

### E. 帧浏览与标注类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/session/{id}/frames` | 分页浏览会话帧 |
| GET | `/api/session/{id}/frame/{index}` | 单帧摘要 |
| GET | `/api/session/{id}/frame/{index}/detail` | 单帧完整数据（详情弹窗用） |
| GET | `/api/session/{id}/annotations` | 列出该会话的语言标注 |
| POST | `/api/session/{id}/annotations` | 添加标注（body: {frame_indices, text}） |
| DELETE | `/api/session/{id}/annotations/{entry_id}` | 删除标注 |
| GET | `/api/session/{id}/image/{filename}` | 会话内相机图像 |

### F. 视觉类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/image/latest` | 前置相机最新帧（RGB） |
| GET | `/api/depth/color` | 深度相机彩色图 |
| GET | `/api/depth/image` | 深度相机深度图（近红远蓝） |
| GET | `/api/depth/status` | 深度相机状态 |
| GET | `/api/lidar/cloud` | 最新激光点云（含强度） |

## 三、前置条件检查（启动前必看）

### 硬件/网络就绪
1. **机器狗开机**，且 80 服务器能 ping 通机器人专网：
   ```bash
   ping 192.168.123.161   # 能通才算机器人网络 OK
   ```
2. **机器狗网卡** enp0s31f6 是 UP 状态且有 IP：
   ```bash
   ip addr show enp0s31f6   # 应显示 192.168.123.222/24 且 state UP
   ```
3. **InfluxDB 在运行**（8086 端口，存储历史数据用）：
   ```bash
   curl http://127.0.0.1:8086/ping   # 返回 204 即可
   ```
4. **Python 虚拟环境已建好**：`/home/dell/go2w_vla/.venv/`
5. **依赖已装**：fastapi、uvicorn、requests、pyarrow、unitree_sdk2py

### SSH 登录
所有操作都在 **80 服务器**上，SSH 登录：
```bash
ssh dell@192.168.1.80    # 密码 123456
```

## 四、手动启动步骤（按顺序执行）

> 用 tmux 让服务在后台常驻（关掉 SSH 也不停）。每条命令先 `source` 环境。

### 第 0 步：准备好环境变量（每个新终端都要先执行）
```bash
cd /home/dell/go2w_vla
source /opt/ros/humble/setup.bash
source .venv/bin/activate
```

### 第 1 步：启动状态采集器 collector.py
```bash
cd /mnt/85ee0fe8-b944-40f5-8474-40cc274f0cef/go2w-monitor
tmux new-session -d -s go2wcol "python collector.py --interface enp0s31f6 --influx-url http://127.0.0.1:8091 --database go2w_monitor --camera"
```

> 作用：订阅机器人 DDS 状态（500Hz），写 InfluxDB 和 state.json。
> 注意：InfluxDB 端口如果是 8091 就用 `--influx-url http://127.0.0.1:8091`。

### 第 2 步：启动激光点云采集 pc_worker.py
```bash
cd /mnt/85ee0fe8-b944-40f5-8474-40cc274f0cef/go2w-monitor
tmux new-session -d -s pcworker "python3 pc_worker.py"
```

> 作用：订阅 ROS2 点云话题，写 pc_cache.json 供三维可视化用。

### 第 3 步：启动前置相机采集 front_cam_worker.py
```bash
cd /mnt/85ee0fe8-b944-40f5-8474-40cc274f0cef/go2w-monitor
tmux new-session -d -s frontcam "python front_cam_worker.py --interface enp0s31f6 --fps 10"
```

> 作用：采集机器狗前置相机画面，写 latest_front.jpg。
> 注意：这个进程和 collector 的 --camera 独立，取其一即可。如果第1步带了 --camera，
> 第3步可以省略；反之同理。推荐用独立进程（更稳定）。

### 第 4 步：启动 Web 服务 server.py
```bash
cd /mnt/85ee0fe8-b944-40f5-8474-40cc274f0cef/go2w-monitor
tmux new-session -d -s go2wweb "python server.py"
```

> 作用：启动网页和所有 API，监听 0.0.0.0:8000。

### 第 5 步：确认深度相机（可选，在机器狗扩展坞上）
如果机器狗扩展坞已配置 rs_capture 为 systemd 服务，它会自启，无需手动：
```bash
ssh unitree@192.168.123.18   # 密码 123
sudo systemctl status rs_capture   # 应显示 active (running)
```

### 第 6 步：验证全部服务启动成功
```bash
tmux ls                          # 应看到 go2wcol, pcworker, frontcam, go2wweb
curl http://127.0.0.1:8000/api/health   # 返回 robot_online: true 即成功
curl http://127.0.0.1:8000/api/lidar/cloud?max_points=500   # 有 points 数据
```

### 第 7 步：打开网页
浏览器访问：**http://192.168.1.80:8000**

## 五、查看日志 / 排查问题

### 查看某服务日志
```bash
# 方法1：看 tmux 窗口实时输出
tmux attach -t go2wcol        # 按 Ctrl+B 再按 D 退出
tmux attach -t go2wweb
tmux attach -t pcworker

# 方法2：看日志文件
tail -50 /mnt/85ee0fe8-b944-40f5-8474-40cc274f0cef/go2w-monitor/collector.log
```

### 常见问题

| 症状 | 原因 | 解决 |
|---|---|---|
| `channel factory init error` | 机器人网络未就绪 / 网卡名错 | 检查 `ip addr`，确认 enp0s31f6 UP |
| `/api/health` 显示 offline | 机器人没开机 | 开机并 ping 通 |
| 点云无数据 | pc_worker 没跑 / 话题没数据 | `tmux attach -t pcworker` 看日志 |
| 深度图不更新 | rs_capture 停了 | 到扩展坞 `systemctl restart rs_capture` |
| 网页打不开 | server.py 没起 | `tmux attach -t go2wweb` |

## 六、日常操作速查

### 停止所有服务
```bash
tmux kill-server   # 停掉所有 tmux 会话（所有服务一起停）
```

### 重新启动（一键脚本建议）
把上面的启动命令存成脚本，下次直接运行：
```bash
nano /home/dell/start_go2w_monitor.sh
# 粘贴第 1-4 步的命令
chmod +x /home/dell/start_go2w_monitor.sh
/home/dell/start_go2w_monitor.sh
```
