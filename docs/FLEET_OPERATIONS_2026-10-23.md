# 具身智能机器人综合管理平台 v3：多机器人与作业工作台

## 已实现

平台名称在网页标题、导航、页脚与 FastAPI 元数据中统一为“具身智能机器人综合管理平台”。现有 Go2-W 自动登记为 `go2w-01`。

机器人管理支持接入、修改名称/型号/节点地址、证书校验设置、启停及实时状态查看。编号不可变，节点地址不能重复；存在待执行或活动作业时不能修改该机器人的配置，先完成或取消作业。停用保留作业历史，不删除资产身份。

全局机器人选择器作用于实时监控、数据录制、视觉与点云、标注工作台、文字交互、SLAM 探索。切换采用带 `robot` 和 `tab` 参数的新文档导航，清空旧页面的图像、图表、点云聚合、标注选择和未完成异步请求；不同浏览器标签页可同时查看不同机器人。URL 指定的身份优先于本地保存值；未知或停用编号明确报错，绝不回退到默认机器狗。

数据入口为 `/api/robots/{robot_id}/...`，本地节点转发至现有接口，远程节点转发到其注册的独立监控服务。相机图片、帧图、导出下载、JSON、上传、标注 DELETE、文字指令和运动门禁都使用同一机器人上下文。响应携带 `X-Robot-ID`；API 不缓存，远程下载流式转发。旧 `/api/...` 路径继续兼容本机采集节点。

## 作业工作台

布局包括可切换统计范围、作业队列、执行机器人状态/实时画面、步骤时间线、异常说明、录制会话及事件记录。状态每 3 秒刷新，操作结果由持久化后端读取。

首批真实可执行模板：

| 模板 | 环节 | 成功条件 |
| --- | --- | --- |
| 传感器巡检 | 状态 → 雷达 → 深度 → 结果 | 实际接口返回在线新鲜数据，各环节均通过 |
| 定时数据采集 | 前置检查 → 启动录制 → 持续采集 → 停止并核验 | 会话归属一致、达到计划时长、确认停止且有有效样本 |

采集时长 5～3600 秒。每台机器人按先后顺序串行执行，不同机器人最多 8 个并行执行线程；这不是导航调度或交通避障。

状态流：`queued → running → succeeded / failed`；可请求 `canceling → canceled`。执行器重启、启动结果不明或清理未确认进入 `needs_attention`，阻塞该机器人的后续作业，待操作员核对后取消清理。取消只会停止本作业已确认拥有的录制；其他会话不会被接管或停止。已结束作业不能再次取消，需要重试时新建作业并保留原失败记录。

进度由已核验步骤计算，采集环节增加按已运行时长计算的进度；只有最终样本与停止状态核验成功才到 100%。没有前端计时模拟执行或自动伪造成功。

统计口径公开在页面中：执行率 = 已开始作业 / 全部作业；成功率 = 成功 /（成功 + 失败），取消与待处理不进入成功率分母；无分母时显示“—”。当前列表及统计限于筛选范围内最近 500 条，长期历史仍保留在 SQLite，不冒充全历史总量。

## 接入第二台机器人

在“机器人管理 → 接入机器人”填写唯一编号、名称、型号和独立采集节点的服务 URL（仅主机和端口，无路径/密码）。公网可信证书默认校验；已有自签名内部节点可按实际配置取消证书校验。

**采集节点必须只绑定它自己的机器人。** 同网段多个 Go2 发布同名 DDS 话题时，仅新开一个监控进程不能保证隔离；部署方需使用独立网卡/隔离网络或经过验证的 DDS 域及接口配置，保证状态、相机、雷达、文字服务、录制目录和数据库都属于同一机器人。中心网关不负责把混合的 DDS 数据重新分离，也不会扫描 LAN 或自动向未知机器下发运动指令。

节点需实现现有监控协议：`/api/state`、录制/会话/标注/图像、雷达/地图、文字服务等接口。中心按路径与 HTTP 方法转发，因此现有兼容单机监控节点不必安装中心作业执行器即可接入；其他型号机器人应先实现该协议的节点适配。不能只填写机器狗的 SDK 信令 IP 当作监控服务 URL。

每个节点独立保存数据集与会话，中心保存资产和作业索引。后续新增物理机器人后，仍需做该机器人真实采集与路由验收；本轮没有第二台实机，双节点验证使用回环测试节点，不宣称已验证双实机。

## 后端与维护

- `fleet_store.py`：SQLite 资产、作业和事件，事务保护同机串行占用；数据库 `fleet.sqlite3`，运行数据不提交 Git。
- `fleet_api.py`：中央接口、状态探测和按机器人路由；节点探测最多 8 并行，短时状态缓存 2 秒。
- `fleet_jobs.py`：真实执行器；调用节点 API，保留录制归属，重启后明确中断而非重复执行。
- `web/fleet-context.js`：文档级机器人身份及 API 路由。
- `web/fleet.js`、`web/fleet.css`：资产和作业工作台。
- `collector.py`：本次实机验收发现原“原子写”注释与实际不符，改为临时文件加 `os.replace` 发布状态，避免读取半写入 JSON 导致瞬时离线。首次短时采集遇到瞬时离线的失败历史保留；检查发现上述写入竞态，修复后复测成功。

中央接口：`GET/POST /api/fleet/robots`、`PATCH /api/fleet/robots/{id}`、`GET /api/fleet/templates`、`GET/POST /api/fleet/jobs`、`GET /api/fleet/jobs/{id}`、`POST /api/fleet/jobs/{id}/cancel`、`GET /api/fleet/health`。

使用现有 `go2w-monitor.service` 与单个 Web 进程。新增模块无生产依赖包变更。`FLEET_LOCAL_URL` 默认指向本机 HTTPS 8000，改变监听地址/协议时应同步修改此环境变量；它仅供作业执行器访问本机节点，浏览器仍访问平台地址。

升级前确保没有正在运行的采集作业；保留数据库备份。Web 重启后活动作业进入待处理，核对录制状态后取消或另建作业。数据库使用 WAL，在线备份应使用 SQLite backup API，不能只复制主数据库而漏掉 WAL。

## 验收

服务器环境后端回归 75 项通过（原 57 项 + 新 18 项）；新测试覆盖资产持久化、唯一性、跨节点方法/正文/查询转发、未知/停用机器人隔离、同机串行、实测状态驱动、延迟录制确认、取消会话归属和中断恢复。

浏览器测试覆盖平台改名、机器人切换、八页上下文与 API/图像路由、节点接入、跨标签页刷新、真实后端作业状态机、步骤和统计、手机布局、无效机器人恢复；均为本地隔离夹具，不保存实机画面。复测命令：

```powershell
# 环境需安装 FastAPI / requests / httpx / uvicorn / Playwright
python -m unittest -q test_fleet
python tools/run_fleet_browser.py
```

浏览器夹具仅绑定回环端口 18881/18882，使用 Windows 已安装 Chrome。运行器直接拥有并清理进程，避免 Windows shell 辅助器退出后遗留测试服务。

实机验收包含一台 Go2-W 的传感器巡检和 5 秒定时录制，确认会话停止及样本有效，八页访问无浏览器脚本错误，运动门禁保持关闭。最终汇总见同目录 `fleet_live_2026-10-23.json`，浏览器记录见 `fleet_browser_2026-10-23.json`。

## 本轮未扩展的边界

自动移动、导航巡逻、搬运等作业需要对应的机器人执行器及已验收的定位/导航门禁，本次没有将它们伪装成已支持模板。权限与网络信任沿用现有内网部署；接入不可信节点或跨公网部署前需要独立身份与访问控制设计。前一轮扩展坞 NTP 未同步问题仍按时间域文档单独处理，本次没有改变系统时钟。
